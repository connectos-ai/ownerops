# Product Principles

1. Never interrupt the owner unless only the owner can move work forward.
2. Never build UI that the data model cannot naturally support.
3. Every task has one clear accountable owner or is explicitly unassigned.
4. A message is not a task until it has a clear desired outcome.
5. Prepare as much work as possible before asking for a decision.
6. No task may silently disappear because it moved between surfaces.
7. Every automated recommendation must be explainable.
8. Native Slack features should be used where reliable, but Slack-native must not mean brittle.
9. The open-source version must be honestly useful without DoBoth.
10. Nothing private, proprietary, personal, client-specific, or organization-specific belongs in the public repo.
